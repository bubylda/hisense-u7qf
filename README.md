# Hisense U7QF

Локальная интеграция Hisense 50U7QF для Home Assistant 2026.10+.
Проверена на 50A690FEVS с прошивкой P0219. Поддерживает пульт, громкость,
входы, приложения, настройки изображения, Wake-on-LAN и Audio Only.

## Установка

Через HACS: добавьте `https://github.com/bubylda/hisense-u7qf` как
пользовательский репозиторий типа **Интеграция** и установите **Hisense U7QF**.

Вручную: скопируйте папку `custom_components/hisense_u7qf` в
`/config/custom_components/`.

После установки и перезапуска Home Assistant нажмите кнопку:

[![Добавить в Home Assistant](https://my.home-assistant.io/badges/config_flow_start.svg)](https://my.home-assistant.io/redirect/config_flow_start/?domain=hisense_u7qf)

Укажите IP включённого ТВ и введите PIN, если он появится. Интеграцию также можно
добавить через **Настройки → Устройства и службы → Добавить интеграцию → Hisense U7QF**.
При переходе с `hisense_vidaa` сначала отключите старую запись
этого ТВ; ссылки на сущности в автоматизациях потребуется обновить.

## Пульт

Карточка пульта необязательна: интеграция работает без неё. Она нужна только
для ручного управления с панели Home Assistant. Навигационные кнопки «Влево»,
«OK», «Вверх» и другие скрыты на автоматических панелях по умолчанию, но
сохраняют свои entity_id и работают в автоматизациях. При обновлении ранее
созданные навигационные кнопки скрываются однократно. Их можно снова показать
в настройках сущности. Кнопки управления экраном остаются видимыми.

Для команд пульта также можно использовать `remote.send_command` без карточки.
Для добавления самой карточки выполните следующее действие.

В **Инструменты разработчика → Действия** выполните со своим entity_id:

```yaml
action: hisense_u7qf.get_remote_card
target:
  entity_id: media_player.hisense_u7qf
```

Вставьте содержимое `card` из ответа в **Добавить карточку → Вручную**,
начиная с `type: vertical-stack`. Не вставляйте весь ответ с полями `card`,
`cards` и `entity_ids`: это ответ действия, а не конфигурация карточки.

Пульт использует встроенные карточки Home Assistant, без дополнительных
ресурсов HACS. Он разделён на основные кнопки с джойстиком и «Назад»,
настройки изображения и цифровой блок с цветными кнопками.
Чтобы разместить их независимо, добавьте три ручные карточки из содержимого
`cards.main`, `cards.picture` и `cards.keypad`. Блок `picture` появляется,
если зарегистрированы настройки изображения. Создание доступно и при
отключённом ТВ, пока интеграция загружена.

В настройках интеграции можно включить **Предполагать состояние экрана**.
Audio Only всегда отображается одним тогглом «Только звук»:
включён — экран выключен, выключен — экран включён. После переподключения,
смены входа, выключения ТВ или ошибки команды предполагается, что экран
включён (Audio Only выключен). То же предположение используется при запуске.
В атрибуте `state_source` это отмечено как `assumed_screen_on`; после успешной
команды — `assumed_from_commands`. Это предположение, а не показание телевизора.

## Особенности

Состояние питания определяется по явным событиям ТВ; при наличии поля
`is_power_on` в свежих ответах оно также обрабатывается. На P0219 в полученной
записи такого поля нет, поэтому периодический опрос метаданных не используется.
При подключении, если питание ещё неизвестно, интеграция один раз запрашивает
`gettvstate` с payload `0` через проверенный маршрут `hisenseservice`. На P0219
подтверждён свежий ответ `sourceswitch`: он восстанавливает `on` при старте HA
с уже включённым HDMI. В текущем соединении запрос не повторяется; во время
pairing он не отправляется. Если ответа нет, состояние остаётся неизвестным.
Исключение — явная команда включения через медиаплеер или Remote: при неизвестном
питании она снова запрашивает состояние, даже если стартовый запрос уже был
отправлен. Повторная команда во время ожидания подтверждения не повторяет WoL.
Подключение к MQTT, настройки изображения и сохранённые сообщения не
подтверждают включение. При отсутствии достоверных данных питание и активность
остаются «Неизвестно», без `assumed_state`; потеря связи не подменяется на «Выключено».

В диагностике `power_state_source` показывает источник наблюдения, а
`power_telemetry` — последние поля питания из ответов с отметкой времени
и признаком retained. Поле `fake_sleep_state` собирается для проверки на P0219;
его значения пока не используются для определения питания.

Для проверки протокола без обновления HA запустите из корня репозитория:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install paho-mqtt==2.1.0
.venv/bin/python scripts/capture_power.py --ip TV_IP --seconds 90 > /tmp/hisense-power.jsonl
```

В течение записи оставьте ТВ на HDMI на 15 секунд, затем переведите его
родным пультом в standby на 15 секунд и включите обратно. Скрипт использует
отдельный MQTT client ID, только читает сведения, по умолчанию не отправляет
клавиши и запрос `gettvstate`. JSONL содержит поля питания, названия остальных полей и
признак retained; значения идентификаторов и токенов не выводятся.

В полученной записи P0219 ответы `gettvinfo`/`capability` не содержат полей
питания. Подтверждены события `tvsleep` при выключении и `sourceswitch` при
включении. Отдельной записью подтверждено, что прямой запрос `gettvstate`
с payload `0` возвращает свежий `sourceswitch` при уже активном HDMI.
Для повторной проверки прямого запроса:

```bash
.venv/bin/python scripts/capture_power.py --ip TV_IP --seconds 20 --query-state
```

Оставьте ТВ включённым на HDMI. Этот режим один раз отправляет `gettvstate`
с payload `0`. На некоторых прошивках может появиться PIN; при получении
запроса pairing скрипт остановится без ввода PIN и повторных запросов состояния.
Интеграция использует подтверждённый вариант однократно при подключении,
когда ещё нет живого наблюдения питания.

Для Wake-on-LAN нужен MAC-адрес и включённое сетевое пробуждение на ТВ.
Audio Only работает через меню; фактическое состояние экрана не считывается.
Другие модели и режимы HDR/Dolby Vision аппаратно не проверены.
Подключение использует MQTT/TLS и встроенную общую пару сертификата/ключа
RemoteNOW; проверка серверного сертификата отключена.
